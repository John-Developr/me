## 1. Role & Purpose

This is **John Carlo A. Ylanan's personal portfolio** — a Next.js 15 (App Router) + React 19 + TypeScript site with plain **CSS Modules + global CSS** (no Tailwind, no CSS-in-JS, no UI kit). It includes:

- A single-page home with profile, about, tech stack, experience, featured project, connect, and recent-blog sections
- An AI-generated blog (Gemini → Supabase, generated by a monthly Vercel cron)
- A floating AI chat assistant ("Chat with John", Gemini)
- A contact form that sends email via Nodemailer/Gmail SMTP

Your job is to extend and maintain this codebase **without changing its visual identity**. The design is finished; treat it as fixed unless the owner explicitly asks for a redesign.

## 2. Strict Design Constraints (non-negotiable)

1. **Use existing CSS variables only.** All colors come from the tokens in `src/styles/general/globals.css` (`:root` for light, `.dark` for dark). Never introduce a new hex/rgb color in a component when a token exists. See [DESIGN_SYSTEM.md](docs/DESIGN_SYSTEM.md) for the catalog.
2. **Never edit token values** in `:root` / `.dark` unless explicitly asked. Adding a *new* token is allowed only if no existing one fits, and it must be defined in **both** `:root` and `.dark`.
3. **Every new UI must work in light and dark mode.** Dark mode is a `.dark` class on `<html>` — not `prefers-color-scheme` in CSS. Test both by toggling via the header menu.
4. **Do not add a styling framework** (Tailwind, styled-components, Emotion, MUI, Chakra, shadcn, Framer Motion, etc.). Styling is CSS Modules + `globals.css`.
5. **Keep the layout contract:**
   - Content column max width `var(--content-based-width)` (970px), provided by `.wrapper .content` in `LayoutProvider` — pages must not add their own outer container.
   - Home cards: `padding: 30px; border-radius: 12px; background: var(--container-bg)` with a `.title` row (20px icon + `h3` ending in a period, e.g. `About Me.`).
   - Single responsive breakpoint: **`@media (max-width: 850px)`** (and `useApp().isMobile`, which uses the same 850px value). Don't invent new breakpoints; `462px` exists only for the hero role text.
6. **Primary actions** use `background-color: var(--bg-primary); color: white;` with hover `var(--primary-hover-color)`, radius 8–10px, height 35–40px. Secondary actions use `color: var(--text-secondary)` and no fill. Some buttons also carry the global `liquid_glass_btn` class — reuse it, don't fork it.
7. **Badges/chips** use `border: var(--badges-border); background: var(--badges-bg); color: var(--badges-text); border-radius: 8px`.
8. **Font:** Karla, loaded by `next/font/google` in `src/app/layout.tsx` as the CSS variable `--font-karla` and applied with `font-family: var(--font-karla), sans-serif` on `*`. Don't add fonts or hard-code the family name.
9. **Icons:** inline SVG React components in `src/components/icons/` using `stroke="currentColor"` / `fill="currentColor"`. Don't add an icon library.
10. **Motion:** entrance animation via `useAnimateIn` (fade + 20px rise, ~600ms, staggered delays). Keep new animations subtle and consistent with existing keyframes.

## 3. Coding Standards

### TypeScript
- `strict: true` (see `tsconfig.json`). No `any`; prefer explicit interfaces for props and state.
- Path alias `@/*` → `src/*`. Always import via `@/…` for cross-folder imports; relative imports are fine inside the same feature folder.
- Shared types/enums live in `src/utils/types.ts` (e.g. `AIBlogResponse`, `FetchStateEnum`, `ThemeEnum`, `InquiryType`). Add new shared types there, grouped under the existing `// ===== SECTION =====` banners.
- String-literal sets are modelled as `enum` (e.g. `BlogCategoryEnum`) or `as const` objects (e.g. `networkDefine`, `storageKeys`).

### React / Next.js
- App Router. Route files in `src/app/**/page.tsx` are **thin**: export `metadata` and render a container from `src/containers/`.
- Page logic/UI lives in `src/containers/<name>-page/`. Containers that use hooks/state start with `'use client'`.
- Global client state: `useApp()` from `src/lib/.context/AppContext.tsx` (`isDark`, `toggleTheme`, `isMobile`, `pageLoading`, `showModal`). Don't add Redux/Zustand.
- Data fetching from the client goes through **API routes** (`src/app/api/**/route.ts`) and the endpoint registry `src/config/networkDefine.ts`. Never hard-code URLs in components — add them to `networkDefine`.
- Server logic is in class-based services in `src/lib/.services/` (`BlogService`, `ChatService`, `ContactService`). API routes instantiate a service, call it, and return `NextResponse.json(...)` inside `try/catch`.
- Async list UIs follow the **loading → error → empty → data** pattern with a dedicated Skeleton, Empty, and Error component (see `home-page/blog-section/`).
- Use `next/image` for images and `next/link` for internal navigation.
- Storage keys (localStorage, cookies) come from `src/config/storageKeys.ts`.

### Naming & files
| Thing | Convention | Example |
|---|---|---|
| Component files | PascalCase `.tsx` | `BlogSectionCard.tsx` |
| Container folders | kebab-case, `-page` / `-section` suffix | `blog-detail-page/`, `stack-section/` |
| Container entry | `index.tsx` default export | `containers/blog-page/index.tsx` |
| Hooks | camelCase, `use` prefix | `useAnimateIn.ts` |
| Config / utils | camelCase `.ts` | `networkDefine.ts`, `stringHelpers.ts` |
| CSS Modules | `<name>.module.css` in `src/styles/pages/` or `src/styles/general/` | `blog.module.css` |
| CSS class names | kebab-case, accessed as `styles["kebab-name"]` or `styles.single` | `styles["card-divider"]` |
| Global classes | plain strings in `className` | `"header"`, `"liquid_glass_btn"` |

### Exports
- Components, containers, and services: **default export**.
- Hooks: `useMediaQuery` is default; `useAnimateIn`, `useDebounce`, `useFadeOutRemove`, `useChatAssistant` are named. Match the file you're touching.
- Icons: default export per file; frequently used icons are re-exported via the `HomeIcons` object in `src/components/icons/index.tsx`.

### Style of code
- Match surrounding formatting: 2- or 4-space indentation as in the file, double quotes, semicolons.
- Section banners (`// ─── … ───` or `/* ===== … ===== */`) and JSDoc on hooks/services are the house style — keep them when editing.
- Don't leave debugging `console.log` in new code.

## 4. Workflow Rules

### Adding a component
1. Check `src/components/` and the relevant container folder for something reusable first.
2. Put shared UI in `src/components/<area>/`, page-specific UI in `src/containers/<page>/`.
3. Style it in the **existing** module for that page (e.g. home sections → `page.module.css`, scoped under the section class like `.fourth .blog …`). Create a new module only for a new page.
4. Colors/borders/shadows → tokens only. Add `@media (max-width: 850px)` rules if the layout has columns.

### Adding a page
1. `src/app/<route>/page.tsx` — export `metadata` (title, description, openGraph, twitter, `alternates.canonical` using `process.env.NEXT_PUBLIC_BASE_URL`) and render `<XPage />`.
2. `src/containers/<route>-page/index.tsx` — `'use client'` if interactive; compose `<Header />`, `<PageIntro subtitle title intro />`, `<main>`, `<Footer />` (see `projects-page/index.tsx`).
3. `src/styles/pages/<route>.module.css` for page styles.
4. Add the route to `menuItems` in `src/components/header/MenuItems.tsx` and to `src/app/sitemap.ts`.

### Adding an API endpoint
1. Business logic in a service under `src/lib/.services/`.
2. Route handler in `src/app/api/<name>/route.ts`, wrapped in `try/catch`, returning `NextResponse.json`.
3. Register the path in `networkDefine`.
4. Secrets: read from `process.env` server-side only. Never prefix a secret with `NEXT_PUBLIC_`.

### Before finishing
- `npm run lint` and `npm run build` must pass.
- Visually check the change in **light and dark** mode and at **≤850px** width.
- Don't touch unrelated files; don't reformat whole files.
- Update [CHANGELOG.md](docs/CHANGELOG.md) under `Unreleased` for user-visible changes.

## 5. Do-Not-Touch / Handle-With-Care

- `src/app/layout.tsx` — the inline `themeScript` prevents a theme flash; keep it in `<head>` and keep `suppressHydrationWarning`.
- `src/middleware.ts` — clears the chat cookie on every page navigation (by design; chat history is per page load).
- `src/docs/system-instruction.md` and `src/docs/blog-instruction.md` — runtime prompts for Gemini, read from disk by API routes. Editing them changes AI output in production.
- `public/documents/email-template.html` — `{{placeholder}}` names must match `ContactService`.
- `.env` — never read values into output, commit, or log them.
- Folders prefixed with `.` in `src/lib/` (`.context`, `.services`, `.supabase`) are intentional; keep the names.

## 6. Conventions & Gotchas

- The root layout's title template appends ` | John Carlo Ylanan`. Page titles must be short (e.g. `"Projects"`) — never include the suffix yourself, or it shows twice. (`openGraph`/`twitter` titles are not templated, so they keep the full name.)
- Build absolute URLs with `BASE_URL` from `src/config/siteUrl.ts` (trailing slash stripped), never `process.env.NEXT_PUBLIC_BASE_URL` directly.

### SEO conventions
- `metadataBase` is set in `src/app/layout.tsx` from `BASE_URL`.
- Share images are generated by `opengraph-image.tsx` files (`src/app/`, `src/app/contact/`, `src/app/projects/`, `src/app/blog/[slug]/`) through `renderOgImage()` in `src/utils/general/ogImage.tsx`. Don't add `openGraph.images` / `twitter.images` URLs pointing to files that don't exist. For a new page's image, add an `opengraph-image.tsx` next to its `page.tsx`.
